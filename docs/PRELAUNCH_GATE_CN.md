# 矿泉水API正式公布前上线闸门

这份清单用来判断本站是否已经从“熟人可试用”升级到“可收费试运营”。每一项都要有证据，不凭感觉放行。

## 1. 干净发布与回滚

- 发布分支或提交已冻结，版本名固定为 `kqs-api-v0.2.0-beta` 或后续 semver。
- `SUB2API_IMAGE` 使用固定 tag，不使用漂移的 `latest` 作为唯一上线依据。
- 发布前记录线上旧镜像和容器 digest。
- 发布手册见 `docs/RELEASE_RUNBOOK_CN.md`。
- 回滚验证至少跑通 `/health`、登录页和一个已存在用户页面。

## 2. 条款、退款与合规说明

站内应至少公开四份文档：

- `/legal/terms` 服务条款。
- `/legal/privacy` 隐私说明。
- `/legal/refund` 退款与卡密规则。
- `/legal/usage-policy` 可接受使用政策。

登录/注册页启用条款确认。核心口径固定为：

- 本站不是 OpenAI 官方服务，也不是任何第三方官方信息系统。
- 卡密兑换成功后属于已交付数字权益，原则上不自动退款。
- 未兑换卡密、订单异常、重复扣款可以人工核对。
- 滥用、攻击、倒卖、共享账号或违规内容可导致账号和 Key 被限制。

## 3. 数据备份与恢复演练

- 存储默认使用 Cloudflare R2 或其他 S3 兼容服务。
- R2 开通和后台填写步骤见 `docs/R2_BACKUP_SETUP_CN.md`。
- 自动备份每天北京时间 02:30 执行。
- 保留策略：14 天或 30 份，取先达到的限制。
- 每次发布前手动备份一次，记录备份 ID。
- 恢复演练只在临时环境做，验证管理员登录、用户、卡密、余额、Key、设置均存在。
- `scripts/prelaunch-readiness.ps1` 必须显示备份 S3/R2 配置、连接测试、计划任务、备份新鲜度全部通过。

## 4. 风控、额度与限损

发布初期默认邀请制 Beta，不建议立刻全网开放注册。

最低限损配置：

- 新建 Codex Key 默认额度 `15.9 USD`。
- 默认速率保护：5 小时 `5 USD`，1 天 `15.9 USD`，7 天 `34.9 USD`。
- 用户可在理解风险后自行调高，但页面必须说明 `0 = 不限制` 不适合新手。
- 风控先用 `observe` 模式观察 24 小时，再把高置信规则切到 `pre_block`。

上线网络安全配置：

- `security.url_allowlist.enabled` 在公开放量前必须开启，并只放行实际使用的上游或价格源主机；开启后重新跑 Codex 请求烟测。
- Cloudflare Tunnel/Worker 场景使用 Worker 规范化访客 IP 头，并通过 `SERVER_TRUSTED_PLATFORM=cloudflare` 让 Gin 读取 Cloudflare 的 `CF-Connecting-IP`；发布前仍需确认源站没有绕过 Cloudflare 的公网直连入口。
- 当前站点 UI 与 API 同域，`cors.allowed_origins` 留空表示拒绝浏览器跨域请求，是可接受的默认策略；只有另设浏览器前端域名时才配置精确白名单。

每日巡检关注：

- 高消费用户。
- 余额异常下降。
- 上游 `401/429/5xx` 激增。
- 未分组 Key。
- 大量失败兑换或错误卡密。

## 5. 客服与求助闭环

用户页面必须能看到“遇到问题怎么办”。反馈只收集必要上下文：

- 账号邮箱。
- 订单号或套餐。
- 卡密码后四位。
- Key ID，不要完整 Key。
- 出错时间。
- 错误截图或文字。

不要求用户发送完整 API Key、完整卡密、银行卡、验证码、cookie 或账号密码。

## 6. Beta 发布节奏

推荐节奏：

1. 第 0 天：管理员和测试号跑通全链路。
2. 第 1 天：邀请 10 人使用。
3. 第 2 天：扩大到 30-50 人。
4. 第 3 天：如果错误率、备份、客服处理都稳定，再公开公布。

放量指标：

- 注册到兑换转化。
- 兑换到创建 Key 转化。
- 创建 Key 到首次成功请求转化。
- 每日支持问题数量和平均处理时间。
- 最近备份是否小于 30 小时。
