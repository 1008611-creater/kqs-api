# 矿泉水API备份与恢复演练手册

目标：证明数据库真的能恢复，而不是只看到"备份成功"。

## 数据边界

当前后台的备份对象是 PostgreSQL 数据库导出文件，不会抓取成员电脑上的真实数据文件或额外上传目录。数据库中仍包含敏感业务记录，因此恢复环境必须隔离、不可公网共享，并在演练完成后销毁临时数据。

## 1. R2/S3 配置

先按 `docs/R2_BACKUP_SETUP_CN.md` 启用 Cloudflare R2、创建 bucket 和 API token。然后在后台 `数据备份` 页面填写：

- Endpoint：`https://<account_id>.r2.cloudflarestorage.com`
- Region：`auto`
- Bucket：`sub2api-backups`
- Prefix：`backups/`
- Force Path Style：关闭

填写 Access Key ID 和 Secret Access Key 后，先点击测试连接。密钥只保存在后台设置中，不写入仓库和文档。

## 2. 自动备份策略

推荐配置：

- 启用：是
- Cron：`30 2 * * *`
- 保留天数：`14`
- 保留份数：`30`

发布前必须额外做一次手动备份，建议手动备份保留 30 天。

## 3. 恢复演练环境

不要直接恢复生产库。准备一个临时环境：

- 独立 PostgreSQL 数据目录
- 独立 Redis 数据目录
- 独立域名或只绑定本机端口
- 不连接正式 Cloudflare 公开入口
- 不邀请真实用户登录临时环境，不对外展示恢复出来的记录

可以复制 `deploy/.env` 后改数据库目录和端口，确保不会覆盖生产容器。

## 4. 演练步骤

1. 在生产后台创建手动备份，等待 `completed`
2. 在临时环境启动相同版本镜像
3. 登录临时环境管理员账号
4. 在 `数据备份` 页面配置同一个 R2 bucket
5. 选择刚才的备份执行恢复
6. 恢复完成后重启临时环境应用容器

## 5. 验收清单

恢复后的临时环境必须确认：

- 管理员能登录
- 用户列表存在
- 卡密兑换记录存在
- 用户余额正确
- API Key 存在但不在页面长期明文暴露
- 系统设置、登录条款、公告、分组和倍率存在
- `/health` 返回正常
- 演练结束后，临时容器与临时数据库被清理，未将备份文件扩散到本地共享目录

记录演练结果：

```text
演练日期：
备份 ID：
备份完成时间：
备份大小：
恢复环境：
恢复耗时：
验证人：
发现问题：
是否允许正式发布：
```

## 6. 自动化巡检要求

半小时巡检不修改代码，只检查：

- 最近一次成功备份是否小于 30 小时
- 是否存在运行中或失败的备份
- 当前 git 工作区是否有未解释的改动
- 是否有未完成发布验证

如果备份超过 30 小时或连续失败，必须通知用户，不应继续扩大公测使用范围。

本机发布前可直接运行：

```powershell
Set-Location E:\codex\kqsapi
.\scripts\prelaunch-readiness.ps1 -ApiBaseUrl https://api.cauai.fun
```

脚本会自动尝试使用 `deploy/.env` 中的管理员账号登录，只在内存中使用临时 token，并检查 S3/R2 配置、连接测试、定时任务和最近成功备份。若 CI 环境没有本机管理员配置，改用 `-AdminToken $env:SUB2API_ADMIN_TOKEN`。如果管理接口不走公网域名，可加 `-AdminApiBaseUrl http://localhost:18080`。
